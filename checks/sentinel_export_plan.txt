2. SCRIPT ARCHITECTURE & OPERATIONAL WORKFLOW
--------------------------------------------------------------------------------
The script `export_chips_s2.py` is engineered for strict reproducibility,
pixel-perfect spatial alignment, robust data-quality filtering, and safe batching.

A. Data Ingestion & Geometry:
   - Reads `chips.csv` to obtain each chip's native tile, stratum, split, UTM EPSG,
     and bounding coordinates (x0, y1, lon, lat).
   - Constructs native UTM planar geometries:
       ee.Geometry.Rectangle([x0, y1 - 5000, x0 + 5000, y1], proj=f"EPSG:{epsg}", geodesic=False)
   - Configures exact affine transform:
       crsTransform = [10.0, 0.0, x0, 0.0, -10.0, y1]
       dimensions = [500, 500]
     This enforces identical pixel centroids and boundaries as the label chips.

B. Surface Reflectance Collection & Quality Filtering:
   - Collection: COPERNICUS/S2_SR_HARMONIZED (harmonized across pre/post-2022 detector offsets).
   - Filter criteria:
       1. Spatial intersection: .filterBounds(aoi_geom)
       2. Temporal window: .filterDate(f"{year}-01-01", f"{year}-12-31")
       3. Scene cloudiness threshold: CLOUDY_PIXEL_PERCENTAGE < 70
   - Pixel-level cloud & shadow masking (`mask_s2_sr_clouds`):
       • QA60 bitmask: Bit 10 (Opaque clouds == 0) and Bit 11 (Cirrus clouds == 0)
       • Scene Classification Layer (SCL): Rejects SCL values:
           - 3 = Cloud shadow
           - 8 = Cloud medium probability
           - 9 = Cloud high probability
           - 10 = Thin cirrus

C. Annual Compositing & Missing Observation Handling:
   - Spectral bands preserved:
       ['B2', 'B3', 'B4', 'B8', 'B11', 'B12']
       (Blue 490 nm, Green 560 nm, Red 665 nm, NIR 842 nm, SWIR1 1610 nm, SWIR2 2190 nm)
   - Annual composite: Pixel-wise median of valid cloud-masked observations across the year.
   - Observation count band (`n_obs`):
       n_obs = s2_col.select('B2').count().rename('n_obs')
     Explicitly records the number of clean, cloud-free observations contributing to each pixel.
   - Zero-unmasking:
       composite.unmask(0).toUint16()
     Missing or unobserved pixels are explicitly set to 0 (NoData). They are NEVER
     silently interpolated or treated as valid spectral reflectance.

D. Duplicate Prevention & Batch Safety:
   - Queries `ee.data.getTaskList()` before submission to check for active ('READY', 'RUNNING')
     or 'COMPLETED' tasks matching description `s2_{chip_id}_{year}`.
   - Prevents duplicate task submissions and avoids wasting GEE quota.
   - Keeps authentication credentials out of the codebase by utilizing `ee.Initialize(project=...)`
     relying on standard Google Cloud SDK authentication (`earthengine authenticate`).


3. ARCHITECTURAL DECISION: ANNUAL 7-BAND GeoTIFFs VS. 63-BAND STACK
--------------------------------------------------------------------------------
The script defaults to exporting ONE annual 7-band GeoTIFF per chip per year:
    <chip_id>_<year>.tif  (e.g., 43R_r130_c111_2024.tif)
    Bands: [B2, B3, B4, B8, B11, B12, n_obs]

Comparison against a monolithic 63/65-band multi-year stack:

| Criteria | Annual 7-Band Files (Recommended) | Multi-Year 63-Band Stack |
| :--- | :--- | :--- |
| GEE Memory Limits | Low risk; small, isolated annual computations | High risk; GEE "User memory limit exceeded" |
| Failure Isolation | Complete; if 1 year fails/retries, 8 years succeed | Zero; single cloud/orbit anomaly fails all 9 years |
| Training Flexibility | Fast; PyTorch DataLoader loads only requested year | Requires reading & slicing 63-band file in RAM |
| Dataset Modularity | Easily add 2026+ or backfill without rewriting chips | Must re-export the entire monolithic stack |
| File Size | ~3.2 MB per file (fits easily in cache) | ~28.8 MB per file |
| Total GEE Tasks (Nationwide) | 13,500 tasks (easily managed in batches) | 1,500 tasks |

Conclusion: The annual 7-band format guarantees operational robustness and ML training
modularity without risk of GEE export timeout or memory exhaustion.

5. VERIFICATION PROTOCOL (SENTINEL-2 VS. LABEL CHIPS)
--------------------------------------------------------------------------------
After downloading exported Sentinel-2 GeoTIFFs from Google Drive, verify their
spatial and spectral integrity against `labels/<chip_id>.tif` using the built-in
verification utility:

    python3 export_chips_s2.py --verify-file downloaded/43R_r130_c111_2024.tif

The automated check performs:
1. Dimension Verification:
   • Confirms raster shape is exactly (500, 500).
2. CRS Verification:
   • Compares rasterio CRS against label chip CRS (e.g., EPSG:32643).
3. Pixel Resolution & Affine Transform:
   • Checks pixel dimensions (10.0 m, -10.0 m).
   • Verifies affine origin (x0, y1) matches label `lbl_src.transform`.
4. Bounds Check:
   • Verifies bounding box [x0, y1 - 5000, x0 + 5000, y1] matches label `lbl_src.bounds`.
5. Band Descriptions & Data Types:
   • Verifies 7 bands: B2, B3, B4, B8, B11, B12, n_obs.
   • Verifies dtype is uint16.
6. Quality & Observation Count:
   • Checks `n_obs` band statistics: mean observations and percentage of 0-obs pixels.
   • Zero observations (n_obs == 0) indicate areas with 100% persistent cloud cover.

- Raster grid: 500 x 500 pixels = 250,000 pixels per chip.
- Bands: 7 bands (uint16 = 2 bytes per band per pixel).
